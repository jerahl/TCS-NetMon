# TCS Dashboard — Functional Reference for the tcs-nemon Port

Snapshot taken 2026-09-07 from the production Zabbix server (`zabbix`, Zabbix 7.4.9 / MySQL on 10.10.3.165, RHEL 9, Apache + PHP-FPM).
Module version: **tcs_dashboard 1.3.0** (`manifest_version` 2.0, PHP namespace `Modules\TcsDashboard`).

This document describes *what the module does and how*, so the same behaviour can be rebuilt in **tcs-nemon** outside of Zabbix's frontend framework. Every path in this bundle is referenced relative to the zip root.

## 1. Architecture in one picture

```
 Browser (React 18 + Babel-standalone, dark "TCS" theme)
 ┌──────────────────────────────────────────────────────────────────┐
 │ global-nav.jsx  (unified sidebar, ⌘K command palette, tweaks)    │
 │ <page>-app.jsx  (React components, read window.* globals)        │
 │ <page>-bridge.jsx (unpacks SSR boot, polls *.data JSON, writes   │
 │                    window.* globals, dispatches update events)   │
 └───────────────▲──────────────────────────▲───────────────────────┘
                 │ HTML + inline JSON boot   │ fetch() JSON every 3–60 s
 ┌───────────────┴──────────────────────────┴───────────────────────┐
 │ Zabbix frontend  zabbix.php?action=tcs.<page>.view / .data       │
 │   actions/Action<Page>.php      → SSR shell + boot payload        │
 │   actions/Action<Page>Data.php  → JSON rollup (APCu cached)       │
 │   actions/Action<Write>.php     → POST write actions (admin only) │
 │   lib/*Client.php               → external system HTTP clients    │
 └───────┬───────────────┬─────────────┬───────────┬────────────────┘
         │ Zabbix PHP API│ HTTPS       │ HTTPS     │ HTTPS/WSS
   host/item/problem/  ExtremeCloud  PacketFence  Milestone XProtect
   event/history/      IQ (XIQ)      v15 REST     API Gateway
   trigger/proxy/                                 + 3CX XAPI
   hanode/usermacro                               + FortiAnalyzer
                                                  + rConfig
```

**Pattern used by every page:**
1. `Action<Page>` (extends `ActionBase`) validates input, optionally collects a *boot* payload, and renders `views/<page>.view.php`.
2. The view hides Zabbix's own chrome with CSS, loads Google Fonts (Inter, JetBrains Mono), React/ReactDOM/Babel from unpkg.com (a local `assets/vendor/react-dom.production.min.js` and a Babel build pipeline `package.json` → `assets/dist/*.js` exist for air-gapped use), inlines the boot payload as `window.<PAGE>_BOOT`, defines `window.TCS_*_URL` endpoints, kills Zabbix's page-refresh timer, then loads the JSX files in a fixed order (tweaks → primitives → global-nav → bridge → widgets → app).
3. `<page>-bridge.jsx` normalises the boot into the window globals the React components were originally prototyped against (mock data lived in `*-data.jsx`; where a bridge exists the mock is only a fallback shape), then polls `Action<Page>Data` on an interval.
4. `Action<Page>Data` (extends `ActionDataBase`) builds the payload from Zabbix API + external clients, caches it in **APCu** (with `/tmp/tcs_dashboard_cache` filesystem fallback in some actions) and returns JSON. Every payload carries a `sources` map (`live | partial | empty | error | mock`) per section so the UI can show a **source badge** (`SourceBadge` primitive) and degrade honestly to "—" rather than fake numbers.

**Auth:** `ActionBase::checkPermissions` redirects unauthenticated browsers to `index.php?request=<orig>`; `ActionDataBase` returns HTTP 401 `{"error":"unauthenticated"}` so pollers can detect session expiry. Read pages require `USER_TYPE_ZABBIX_USER`; write actions require `USER_TYPE_ZABBIX_ADMIN`. CSRF validation is disabled on all controllers (same-origin JSON fetch). Apache additionally 302s any `action=tcs.*` request lacking a `zbx_session` cookie straight to the login page (`httpd/zabbix.conf`). Host visibility is inherited from the logged-in Zabbix user's permissions because all API calls run as that user.

**Menu:** `Module.php` adds 15 entries under Zabbix *Monitoring*. All page URLs are centralised in `window.TCS_NAV` at the top of `assets/global-nav.jsx`.

## 2. Page-by-page functionality

Status legend: **LIVE** = real data; **PARTIAL** = real data with mock fallbacks for untemplated fields; **MOCK** = renders synthetic data from `*-data.jsx` only.

### 2.1 Global Dashboard — `tcs.global.view` — LIVE
Files: `ActionGlobal.php`, `ActionGlobalData.php` (1151 lines), `global-bridge.jsx`, `global-app.jsx`, `global-data.jsx`, `global.css`.
- KPI totals (hosts up/down, items, triggers, open problems), severity strip, 24 h problem-open timeline, **site-health heatmap**, problems-by-domain cards, active triggers, top hotspots, recent events.
- **Site** = Zabbix host group whose name starts with `Site/` (`{$TCS.SITE.GROUP.PREFIX}` overrides). **Domain** = host bucketed by template-name substring: wireless (`XIQ`, `Extreme AP`, `WLC`), switches (`EXOS`, `switch`, `IOS`), servers (`Linux`, `Windows`, `iDRAC`, `OS by`), nvr (`Milestone`, `XProtect`, `NVR`), voip (`3CX`, `VoIP`, `SIP`).
- Aggregator hosts (fleet-wide alert carriers) are excluded from the per-site heatmap; auto-discovered per-camera hosts are excluded from the whole page because their unpolled SNMP interfaces would count thousands of cameras as "down".
- Pulls per-domain fleet KPIs by reusing the wireless (XIQ), VoIP and surveillance collectors. Zabbix APIs only: `host.get`, `hostgroup.get`, `problem.get`, `event.get`, `proxy.get`, `trigger.get`. Range param `?range=`.

### 2.2 Global search / command palette — `tcs.search.data` — LIVE
`ActionSearchData.php` backs the ⌘K palette in the sidebar. Returns `{results:[{type,cat,label,sub,href,icon}]}` from (1) Zabbix hosts matched by technical name / visible name / interface IP, classified into device kind via template-name substrings and deep-linked to the right TCS page; (2) PacketFence endpoints via `PFClient::searchNodesText()` (MAC / hostname / owner / 802.1X user) enriched with latest `locationlog` row (switch, port, dot1x user); (3) XIQ devices. Caps: 20 hosts, 25 clients, 25 XIQ.

### 2.3 Wireless AP Detail — `tcs.dashboard.view&hostid=N` — LIVE
Files: `ActionDashboard.php` (2045 lines), `ActionDashboardData.php`, `data-bridge.jsx`, `shell.jsx`, `tabs.jsx`, `app.jsx`, `styles.css`. This was the first live page and is the reference implementation.
- **AP Navigator** rail: every wireless host grouped by school (`collectApSites`), with client-load colouring (warn ≥35, high ≥50 clients).
- Device card: model, serial, MAC, IP, firmware, uptime, availability, proxy, PoE draw, CPU/mem/temp, XIQ connected state (`composeApStatus`, `resolveAvailability`, `resolveProxy`, `resolveUptime`).
- Item value map in `collectItems()` (`$key_map`) — logical name → Zabbix item key. `resolveXiqFleetFields()` fills gaps from the fleet master item `xiq.devices.raw`.
- System / network info from host inventory (`collectSystemInfo`, `collectNetworkInfo`).
- Alerts: active triggers, last-24 h counts by severity, last-fired age (`collectAlertsSummary/Detail`); event list (`collectEvents`).
- **Wired uplink**: `collectWiredPorts` + `collectPfApUplink` — finds the switch/port the AP hangs off by querying PacketFence locationlog for the AP's eth0 MAC (`normalizeMacForPf`, `resolveSwitchHostid`), linking to the Switches page.
- **SSIDs** (`collectSsidList`) and **live XIQ clients** (`collectXiqClients` → `XIQClient` `/clients/active?deviceIds=…&views=FULL`) with RSSI/SNR/OS/SSID.
- **PacketFence clients / auth failures** on this AP (`collectPacketFence` → `PFClient`), plus link to PF admin UI (`{$PF.ADMIN_URL}`).
- Write buttons wired: **Reboot AP** (`tcs.xiq.ap.reboot`), **Cycle PoE** on uplink (`tcs.switch.cyclepoe`), **Reevaluate access / Restart switchport** on a client (`tcs.pf.device`).
- Polls `tcs.dashboard.data` every 30 s.

### 2.4 XIQ Wireless Status (fleet) — `tcs.xiq.view` — LIVE

## 4. Milestone external scripts + `/var/lib/zabbix` state files

`ExternalScripts` is the default `/usr/lib/zabbix/externalscripts`. Pattern: a slow **refresh** job (cron) writes a JSON snapshot atomically (temp file + rename, `flock` against overlap, stderr to `/var/log/zabbix/<name>.log`, an `.err` marker on failure), and a millisecond **read** script that Zabbix calls as an external-check item just `cat`s the file — with a staleness guard that emits `{"error":"stale_snapshot"...}` if the file is older than MAX_AGE.

| Family | Refresh (cron, zabbix user) | Reader item key | Output | Source API |
|---|---|---|---|---|
| cameras | `*/15 * * * *` `milestone_cameras_refresh.sh <host> <user> <pass> --scheme https` → `milestone_cameras_state.py` | `milestone_cameras_read.sh[3600]` | `/var/lib/zabbix/milestone_cameras_state.json` — `{__count, __fetched_at, __hardware_count, __mac_count, __array:[...], <cameraGuid>:{...}}`; each camera carries displayName, enabled, recording settings, `address` (bare IP normalised from `http://x/`), `mac` (normalised `AA:BB:..`), `macRaw`, `hardwareId/Name/Model` | XProtect REST `/api/rest/v1/cameras` + `/hardware` (includeChildren variants tried for MAC) |
| ess (event state) | `15 3 * * *` `milestone_ess_refresh.sh …` → `milestone_ess_state.py` (1–2 min at 2500+ cams) | `milestone_ess_read.sh[]` (MAX_AGE 48 h) | `/var/lib/zabbix/milestone_ess_state.json` — `{count, cameras:{<guid>:{states:[{type, stategroupid, time, source}]}}}` | XProtect **ESS WebSocket** `wss://…/api/ws/events/v1` (OAuth token → authenticate → startSession → addSubscription all types → getState; keepalive ping disabled) |
| groups | not currently scheduled (scripts present, mode 0644, `milestone_groups_*`) | `milestone_groups_read.sh[3600]` | `/var/lib/zabbix/milestone_groups_state.json` (absent) — flat rows per Smart Client camera group with direct cameras | `/api/rest/v1/cameraGroups?includeChildren=cameras`, depth-first |

## 7. Frontend conventions worth carrying over

- **Design tokens** in `assets/styles.css` (dark `#0d1117` background, TCS red `#d92929` accent, Inter + JetBrains Mono); per-page CSS files layer on top.
- `primitives.jsx`: `Icon`, `SourceBadge`, cards, rings, sparklines. `tweaks-panel.jsx`: a settings flyout (density, hide source badges, etc.) using `useTweaks()`; sidebar collapse persisted in `localStorage` key `tcs.sidebar.collapsed`.
- Boot splash inside `#root` until React mounts; Zabbix `PageRefresh` timer and `<meta refresh>` are killed so React state (selected port/tab) survives.
- Bridges dispatch DOM events (e.g. `tcs:surveillance-ws-update`) rather than touching the DOM; React re-renders from window globals.
- Build: `npm run build` (Babel preset-react) compiles `assets/*.jsx` → `assets/dist/*.js`; views currently still load the JSX via Babel-standalone from unpkg.
